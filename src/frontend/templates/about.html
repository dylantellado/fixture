How Fixture works

Fixture will handle the back-and-forth of scheduling emails for you, without ever breaking a rule you've set. First, it needs a memory of your past scheduling threads. That's what this milestone builds: a private, searchable index of each person's emails.

From inbox to answer

  1. 1
    Ingest

    Checks the generated email threads and removes duplicates.

  2. 2
    Preprocess

    Turns each thread into clean messages and replaces email addresses and phone numbers with placeholders. Every message keeps a scheduling label, like Proposed times or Reschedule.

  3. 3
    Index

    Turns each message into an embedding (all-MiniLM-L6-v2) and stores it in that person's own ChromaDB collection.

  4. 4
    API

    Searches one person's collection per request and returns the closest messages, best first.

  5. 5
    This app

    Lets you pick a mailbox and ask a question on the Search page.

All five run as separate Docker containers, started in order with one command: docker compose up.

Private by design

  • One collection per person. A search opens exactly one mailbox's collection, so it can't return someone else's email, even when two people write to the same contact.
  • The app chooses the mailbox. Which mailbox to search always comes from the app, never from an AI model or from text inside an email.
  • Anonymized and read-only. Addresses and phone numbers are replaced before indexing, and nothing here sends email or changes a calendar.
